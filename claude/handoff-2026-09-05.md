## Decisions and why

- **Money never touches the app.** Venmo between friends. A platform collecting fees is a gambling operator. Non-negotiable.
- **No chat notifications, only two push alerts.** Alerts stay rare so people keep them on.
- **Projections only over started games.** Projecting over hidden picks would leak them.
- **Featured slates freeze on first sight; swaps only by the commissioner; a kicked-off game can't be removed.** Rankings move; a slate must not.
- **Scoring mode locks at the first entry.** A season decision, never a mid-week one.
- **The line at kickoff is the line.** Re-syncs never change a started game's spread and never erase one ESPN stops sending.
- **Independents are not a power conference** in the featured rule (Notre Dame gets in on rank; UMass at UConn shouldn't).
- **Skip FCS opponents whoever hosts.** Everyone picks the same side; nothing is decided.
- **Ads: not in this build.** Colin wants an ad-supported version as a separate branch later: opt-in rewarded ads only (a "chest" that unlocks non-competitive perks like projections or the roast), never interrupting picks, **no in-app purchases ever**. Reasoning already given: ads at one league earn nothing and cost trust; get to several leagues first; the share card is the real growth engine. Wide-screen dead space is future ad real estate; for now it holds games.
- **Mobile first.** Desktop and ultrawide get reasonable treatment, no more.
- **Chat exists because Colin asked**, over the assistant's initial "the group text already exists" argument. His call.

## Working conventions (these prevented outages)

1. **SQL before merge, every time.** Code that writes new columns lands before the columns exist → the score sync fails quietly. Every migration is safe to run twice; when unsure, run them all in date order.
2. **One PR per feature, branched from `main` after the previous merge.** Stacking branches caused the #12 conflicts (three branches appended at the same anchors in `actions.js`, `schema.sql`, `policy-test.sql`, `reset.sql`, README).
3. **Every PR body:** what it does in plain English, what was verified, and the exact clicks Colin must do. Attach SQL files in chat as well.
4. **Self-checks:** `npm run check` runs seven pure test files (`lib/**/*.test.mjs`). New logic gets a test, and new tests get mutated once to prove they can fail.
5. **Policy tests:** `npm run check:db` against a local Postgres (`initdb` as the `postgres` user under `/var/lib/postgresql`, port 5433, `DATABASE_URL=postgres://claude:claude@127.0.0.1:5433/pool`). 64 checks as of today. Later test blocks run after earlier ones delete the NFL test league (id …0001); use the college league (…0007) or the stranger's (…0002) for late fixtures.
6. **Visual checks:** build, `npm start` on port 3100 with stub Supabase env and `ALLOW_PREVIEW=1`, drive `/dev` views with Playwright (`/opt/node22/lib/node_modules/playwright`). Views: picks, board, admin, epl, featured, cfb, notify, spread, chat, `/dev/share`. "Simulate a score" button exercises the glow.
7. **Sandbox gotchas:** ESPN and `a.espncdn.com` are unreachable (stub logos via route fulfill; rank/odds shapes were written from knowledge, verified on the live site by Colin's screenshots). Headless Chromium pins `Notification.permission` to `denied` (stub it). Kill servers with `pgrep -f "next-serve[r]"` (a plain pkill matches your own shell). Always confirm the served CSS hash matches `.next/static/css` or you are measuring a stale build. Satori (`next/og`) wants one string per text node and explicit `display:flex` on multi-child boxes. A grid item needs `min-w-0` or one nowrap string widens the page.
8. **Commit trailers:** `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` and the session link. No model names in code or PR bodies.
